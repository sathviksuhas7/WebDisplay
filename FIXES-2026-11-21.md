# WebDisplay usability and banking updates – 21 Nov 2026

This update addresses the latest test feedback:

- Faster logout response by removing the broad Clear-Site-Data cache purge; session invalidation and no-store headers remain.
- Failed login uses Post/Redirect/Get, retains the username only, and never retains the password.
- Login CSRF error message is shorter; login CSRF token remains stable across repeated login-page requests.
- Login Back navigation no longer cycles through prior failed-login form submissions.
- Temporary-password customers can use the change-password page without the session-heartbeat redirect loop.
- OTP verification actions appear before resend actions.
- Indian mobile number fields accept only 10 digits; backend validation is also applied.
- Employee account creation now asks for Savings or Current account type.
- Customer transaction history has All, Deposit, Withdrawal and Transfer filters.
- Customer account statements can be opened or downloaded as PDF for a selected date range.
- A new transfer attempt clears the previous transfer message.
- Helpdesk agent-created tickets on behalf of customers are initially assigned to that agent. The Helpdesk Manager can reassign them; Bank Manager remains a separate role.
- Wrong-role page access shows a friendly Access Denied page.
- Optional local ELK configuration collects multiple `.log` files from `logs/`.

## Required database migration

Before starting the updated application, run `database/account-type-migration.sql` once against `webdisplay_db`. It adds `accounts.account_type` and defaults existing accounts to `SAVINGS`.

Also ensure the earlier `database/remaining-work-migration.sql` has already been applied for `app_settings`.

## ELK

ELK is optional. Start it only if Docker Desktop is installed and running:

```bash
docker compose -f elk/docker-compose.yml up -d
```

See `elk/README.md`. The included stack disables Elasticsearch security and is for local development only.
